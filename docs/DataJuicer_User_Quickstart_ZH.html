Data-Juicer 内部用户能力说明

重点能力

本文档面向业务用户和 pipeline 使用者，概述 Data-Juicer 的主要能力、YAML 配置结构、 HDFS / Magnus / Hive 的接入与导出方式，以及近期新增的限量导出、Ray HDFS 分布式写出、 checkpoint 和单样本 debug 能力。

输入 Ray remote 模式下接入 HDFS、Magnus、TQS、Hive 等内部数据源。
处理 通过 YAML 组合 mapper、filter、dedup 等算子。
输出 优先使用 HDFS 或 Magnus，支持限量导出。
恢复 通过 Ray Data checkpoint 和单样本 operator trace 辅助定位问题。

1. 能力概览

对业务用户而言，Data-Juicer 的核心使用方式是通过 YAML 描述数据处理流程： 从输入源加载数据，按顺序执行算子处理，并将结果写入稳定的目标存储。

Input Loader 从 HDFS、Magnus、TQS 或 Hive 读取远程数据。
→
Contract Schema 明确字段名、类型、分区和列裁剪边界。
→
Compute Process 按 YAML 顺序执行 mapper、filter、dedup 等算子。
→
Output Export 写入 HDFS 或 Magnus，必要时使用限量导出。
验证 通过 Ray dry-run、export.max_rows 和单样本 operator trace 降低上线前定位成本。
恢复 通过 Ray Data checkpoint 保留已完成写出进度；需要 exactly-once 文件清理语义时开启 delete_no_checkpoint_files。
建议优先掌握三类配置：dataset.configs、process 和结构化 export。 算子参数可按任务需要查阅，不要求在首次使用时完整掌握。

2. 平台介绍

AI DataCenter 平台面向数据资产、算子资产、任务和工作流提供统一入口。本文先介绍与 Data-Juicer 使用最直接相关的三个模块：数据集管理、算子管理 和 任务管理。 平台中的其他模块后续可继续补充。

数据集管理

管理可复用的数据资产

数据集管理用于查看数据集名称、英文名、数据源 ID、数据类型、负责人、更新时间、标签和接入状态。 用户可以从列表进入详情页，确认样例数据和结构信息，再决定后续 YAML 中的 loader、字段名和列裁剪范围。

算子管理

管理可复用的数据处理能力

算子管理用于查看 mapper、filter、deduplicator 等处理能力。用户可以按分支、类型、名称、描述或负责人筛选算子， 并在详情页确认算子英文名、代码位置和参数定义。

任务管理

编排并运行处理流程

任务管理用于把数据集节点、算子节点和标注节点组织成可上线、可执行的工作流。 用户可以在画布中调整节点顺序，在右侧配置数据源、schema、分区和参数，并通过预览、保存、上线和执行完成任务发布。

数据集管理

页面区域主要能力对 Data-Juicer 使用的价值
数据集列表 按数据集名称、描述、负责人、数据域、数据类型和标签筛选，并查看更新时间、负责人和详情入口。 用于定位可接入的数据资产，确认是否已经有稳定的数据源可作为任务输入。
数据集详情 展示英文名称、数据源 ID、数据类型、负责人、更新时间、标签、RAG Ready 和训练接入优先等基础信息。 英文名称和数据源 ID 可作为跨平台沟通的稳定标识，数据类型用于判断后续 loader 和 export 方案。
数据样例 支持 JSON 视图和表格视图，展示样本中的真实字段和值。 用于上线前检查字段内容是否符合预期，尤其是长文本、列表字段、嵌套字段和空值情况。
结构信息 展示字段序号、字段名、中文名、数据类型和描述。 用于编写 YAML 时确认 columns、text_key、分区字段和算子输入输出字段。
数据接入 从数据集详情页进入接入流程。 用于把已登记的数据资产接入后续处理链路，减少手工复制路径和字段信息的错误。
使用 Data-Juicer 前，建议先在数据集详情页查看“数据样例”和“结构信息”。这一步可以提前发现字段名不一致、 字段类型不符合预期、样本内容为空或字段过长等问题。

算子管理

页面区域主要能力对 Data-Juicer 使用的价值
算子列表 按代码分支、算子类型、名称或描述、负责人筛选算子资产。 用于快速找到可复用的清洗、过滤、增强、打分或导入类算子，避免重复开发。
算子卡片 展示中文名、英文名、算子类型、负责人、更新时间和简要描述。 英文名通常对应 YAML process 中使用的算子名，是编写配置时最关键的信息。
算子详情 展示中文名、英文名、算子类型、算子 ID、代码分支、代码仓库链接和描述。 用于确认算子来源和实现位置；当行为不符合预期时，可以通过代码链接进一步核对实现。
参数介绍 展示参数名称、字段描述、类型、是否必填和默认值。 用于把平台参数表转换为 YAML 参数，并确认哪些参数必须显式填写、哪些参数可使用默认值。
编写 process 时建议从算子详情页复制英文名，并按参数表填写 YAML。对于模型型、多模态或依赖外部服务的算子， 还需要结合代码仓库链接确认资源、依赖和运行环境要求。

任务管理

页面区域主要能力对 Data-Juicer 使用的价值
工作流信息 展示工作流 ID、上线状态、版本号和当前空间，支持返回、保存、上线和执行。 用于确认当前编辑的是哪个任务版本，并区分草稿配置、已上线配置和实际执行入口。
节点面板 按算子分支展示基础节点、业务算子和图片算子等节点资产，并支持按节点名称或英文名搜索。 用于把平台中的数据集、算子和标注能力拖入工作流，形成可视化的数据处理链路。
工作流画布 以有向链路展示数据集节点、处理算子、结果输出和人工审核等节点顺序，支持缩放、布局优化和执行预览。 用于检查 Data-Juicer pipeline 的执行顺序，避免 YAML 中常见的算子顺序错误和输出节点遗漏。
节点配置 右侧配置当前节点的节点名称、数据源、schema 信息、分区信息和参数。 用于把可视化节点落到具体输入输出配置，例如选择 Lance 数据集、设置建表参数或补充分区字段。
基础信息与资源配置 配置任务基础信息和执行资源，并与保存、上线、执行流程配合使用。 用于将已经验证的处理流程提交到平台运行环境，减少本地 YAML 与线上执行配置不一致的问题。
任务管理更接近 Data-Juicer 的平台化编排入口。使用时建议先完成节点配置和执行预览，再上线执行； 对关键输出节点，应重点确认数据源类型、schema、分区和参数是否与目标导出要求一致。

3. YAML 配置结构

本文中的 YAML 均以 Ray remote 任务为前提。一份任务配置通常包含四段： 任务运行环境、远程输入数据、处理算子和结果导出。

最小结构YAML
project_name: <your_project_name>
executor_type: ray              # fixed in this guide
ray_address: auto
work_dir: ./outputs/<job_name>

dataset:
  configs:
    - type: remote               # fixed in this guide
      source: hdfs               # common: hdfs | magnus | tqs | hive
      path: hdfs://<cluster>/<path>/input

process:
  - text_length_filter:
      min_len: 10
  - whitespace_normalization_mapper: {}

export:
  target: hdfs                   # common: hdfs | magnus
  type: jsonl                    # common: jsonl | parquet
  path: hdfs://<cluster>/<path>/output/{job_id}
  mode: error_if_exists          # enum: error_if_exists | overwrite | append
配置块重点关注项边界说明
dataset.configs 远程数据源、路径、字段列、limit、读取并发。 Ray HDFS 直读当前主路径是 Parquet；Hive 依赖内部 byted-ray。
process 算子按顺序执行；每个算子是一个 YAML map。 算子参数必须和字段类型匹配，复杂二进制字段要特别注意 schema。
export 目标、格式、写入模式、行数限制、schema、分区。 新任务建议用结构化 export，不要继续依赖旧式 export_path。
checkpoint Ray 文件 source-to-sink 写出恢复策略。 本文仅介绍 ray_data_checkpoint，不展开默认 executor 的 checkpoint。

4. 算子示例

process 是一个有序列表，Data-Juicer 会按 YAML 中的顺序执行算子。 常见算子可以粗略分为 mapper、filter 和 deduplicator：mapper 改写样本字段，filter 过滤样本， deduplicator 做跨样本去重。业务用户通常只需要理解算子输入字段、输出影响和资源要求。

类型示例算子典型用途注意点
Mapper whitespace_normalization_mapper 标准化文本中的空白字符，并去掉首尾空白。 默认处理 text_key 指定的文本字段。
Filter text_length_filter 按文本长度保留样本，例如过滤过短或过长文本。 min_len 默认 10，max_len 默认不设实际上限。
Filter language_id_score_filter 按语言识别结果和置信度保留样本。 依赖 FastText 模型，适合在资源和模型准备明确后使用。
Deduplicator document_deduplicator 基于文本 hash 做文档级精确去重。 会跨样本判断重复，通常放在基础清洗和过滤之后。
多模态 Filter image_text_similarity_filter 基于 CLIP 计算图文相似度并过滤样本。 属于模型型算子，代码声明使用 cuda，需要确认 GPU 资源和依赖。

文本清洗链路

文本 mapper / filter / dedupYAML
process:
  - whitespace_normalization_mapper:
      text_key: text              # default: text
  - text_length_filter:
      text_key: text              # default: text
      min_len: 20                 # default: 10
      max_len: 4096               # default: sys.maxsize
  - language_id_score_filter:
      text_key: text              # default: text
      lang: zh                    # default: ""; empty means only score filtering
      min_score: 0.8              # default: 0.8
  - document_deduplicator:
      text_key: text              # default: text
      lowercase: false            # default: false
      ignore_non_character: false # default: false

多模态过滤示例

图文相似度过滤YAML
process:
  - image_text_similarity_filter:
      text_key: text              # default: text
      image_key: images           # default: images; keep aligned with input schema
      hf_clip: openai/clip-vit-base-patch32
      min_score: 0.2              # default: 0.1
      max_score: 1.0              # default: 1.0
      any_or_all: any             # default: any; enum: any | all
      reduce_mode: avg            # default: avg; enum: avg | max | min

模型型或多模态算子通常对依赖、模型下载、GPU 和字段 schema 更敏感。上线前建议先用 ray_dry_run_plan、export.max_rows 和单样本 debug 验证。

5. Loader 选择建议

推荐优先级：HDFS Parquet / Magnus 优先。TQS loader 仅建议测试或小规模验证使用； 大规模任务建议先物化到 HDFS Parquet，再使用 HDFS loader。Hive 可用但不建议作为稳定交付的首选入口。

HDFS Loader，推荐大规模稳定读取

Ray 模式下推荐从 HDFS 读取 Parquet。适合上游已经把数据落成文件，或者从 TQS / Hive 物化出中间结果后再处理。

Ray HDFS Parquet 读取YAML
executor_type: ray
ray_address: auto

dataset:
  configs:
    - type: remote
      source: hdfs
      path: hdfs://<cluster>/<path>/input_parquet_dir
      format: parquet             # default: parquet; Ray HDFS loader currently supports parquet
      filesystem: pyarrow         # default: pyarrow; enum: pyarrow | webhdfs; webhdfs is for tests only
      columns: ["text", "label", "p_date"]  # default: null; column pruning, unset means all columns
      limit: 1000                 # default: null; limits rows entering process/export
      override_num_blocks: 128    # default: null; target Ray block count, Ray decides when unset
      concurrency: 64             # default: null; Ray parquet read concurrency, Ray decides when unset

filesystem: webhdfs 主要用于测试环境；线上 Ray 集群通常使用 pyarrow。

参数默认值说明
filesystem pyarrow HDFS filesystem 实现。线上 Ray 环境使用 pyarrow；webhdfs 仅用于测试环境验证。
columns null 列裁剪配置。配置后只读取指定列；未配置时读取全部列。
override_num_blocks null 期望的 Ray block 数。适合需要控制后续并行度或 block 粒度时设置；未配置时由 Ray 决定。
concurrency null Ray Parquet 读取并发。用于限制或提高读取任务并发；未配置时由 Ray 决定。

Magnus Loader，推荐读规范化表

如果数据已经在 Magnus 表里，并且 schema 清晰，直接读 Magnus 可以减少中间文件管理。 filter 指 Magnus / Iceberg 侧 partition filter，用于分区裁剪；其他读取参数通过 magnus_conf 透传给 pyiceberg.ray.read_magnus。

Magnus 读取YAML
executor_type: ray
ray_address: auto

dataset:
  configs:
    - type: remote
      source: magnus
      table_name: <db>.<table>
      filter: "p_date = '20260520'"  # default: null; partition filter
      magnus_conf:
        parallelism: 1               # default: 1; read task parallelism
        concurrency: null            # default: null; Ray datasource read concurrency
        batch_size: 256              # default: 256; rows per reader batch
        snapshot_id: null            # default: null; read a specific snapshot when set
        selected_fields: null        # default: null; column pruning, unset means all columns
        enable_bucket_aware: false   # default: false; bucket-aware read for supported partitioned tables
        ray_remote_args: null        # default: null; Ray remote args for read tasks
        read_options: {}             # default: {}; options passed to MagnusClient / reader
        location: null               # default: null; table location, normally use table_name instead
参数默认值说明
filter null Magnus / Iceberg partition filter。推荐用于按分区裁剪读取范围。
magnus_conf.parallelism 1 传给 read_magnus 的 read task parallelism。
magnus_conf.concurrency null Ray datasource 读取并发。未设置时由 Ray / pyiceberg 默认逻辑决定。
magnus_conf.batch_size 256 Magnus reader 每批读取行数。
magnus_conf.selected_fields null 列裁剪配置。配置后只读取指定字段；未配置时读取全部字段。
magnus_conf.snapshot_id null 指定读取的 snapshot。未配置时读取当前默认 snapshot。
magnus_conf.read_options {} 透传给 MagnusClient / reader / planner 的选项。
magnus_conf.enable_bucket_aware false 是否启用 bucket-aware 读取。仅适用于底层支持的分区表。
magnus_conf.ray_remote_args null 传给 Ray read task 的 remote 参数。
magnus_conf.location null 按表 location 读取时使用。常规内部表建议优先使用 table_name。

TQS Loader，仅建议测试使用

TQS loader 不推荐大规模直接使用，建议仅用于小样本测试、配置联调或上线前快速验证。 Ray TQS loader 不提供受支持的 Ray Data checkpoint source boundary，因此 ray_data_checkpoint 以及依赖 source-to-sink checkpoint 的恢复能力无法开启。生产或大规模处理建议先将 TQS 查询结果物化为 HDFS Parquet，再切换到 HDFS loader。
TQS 小样本读取YAML
executor_type: ray
ray_address: auto

dataset:
  configs:
    - type: remote
      source: tqs
      read_mode: client_result    # for tests / small samples only
      query: "select id, text from <db>.<table> limit 100"
      tqs_app_id: <tqs_app_id>   # do not write real secrets into shared YAML
      tqs_app_key: <tqs_app_key>
      user_name: <user_name>
      tqs_cluster: cn             # default: cn
      tqs_timeout: 120            # default: 120

如果任务需要 checkpoint、分布式稳定读取、列裁剪或更可控的并发，优先使用 TQS 物化后的 HDFS Parquet 路径。

Hive Loader，可用但不是首选

Hive loader 只支持 Ray 模式，并依赖内部 byted-ray。它的稳定性和可排障性通常弱于 HDFS Parquet / Magnus 路径， 尤其容易受 schema、分区、底层 reader 行为和集群环境影响。稳定交付时，建议先将 Hive/TQS 结果物化到 HDFS，再使用 HDFS loader。
Hive 读取YAML
executor_type: ray
ray_address: auto

dataset:
  configs:
    - type: remote
      source: hive
      table_name: <db>.<table>
      columns:                    # default: null; column pruning and optional type cast
        - text
        - label
        - name: user_id
          cast: BIGINT             # enum: STRING | BIGINT
      filter: "p_date = '20260520'"  # default: null
      concurrency: 64              # default: null; Ray Hive read concurrency
      override_num_blocks: 128     # default: null; target Ray block count

6. Export 选择建议

新任务建议优先使用结构化 export。文件型结果优先写入 HDFS；表型结果优先写入 Magnus。

HDFS Export，推荐文件型结果

Ray 模式下，parquet 和 jsonl 可以由 Ray workers 分布式写到 HDFS 目录。 这是大规模输出的推荐路径，也是和 Ray Data checkpoint 配合时的主路径。

写 HDFS ParquetYAML
export:
  target: hdfs
  type: parquet
  path: hdfs://<cluster>/<path>/result/{job_id}
  filesystem: pyarrow             # default: pyarrow; enum: pyarrow | webhdfs; webhdfs is for tests only
  mode: error_if_exists           # default: error_if_exists; enum: error_if_exists | overwrite | append
  extra_args:
    max_rows_per_file: 10000      # default: null; parquet writer row/file control
    concurrency: 64               # default: null; Ray writer concurrency
写 HDFS JSONLYAML
export:
  target: hdfs
  type: jsonl
  path: hdfs://<cluster>/<path>/result/{job_id}
  filesystem: pyarrow             # default: pyarrow; enum: pyarrow | webhdfs; webhdfs is for tests only
  mode: append                    # default: error_if_exists; enum: error_if_exists | overwrite | append
  extra_args:
    min_rows_per_file: 10000      # default: null; JSONL datasink starts a new file after this row threshold
    concurrency: 64               # default: null; Ray writer concurrency
mode适合场景注意点
error_if_exists 默认安全模式，避免误覆盖已有结果。 目标目录存在时会失败，重新执行前需要清理或更换路径。
overwrite 明确希望覆盖同一路径的测试任务。 会删除已有目标，不适合保留上次失败进度。
append 希望保留已写 part 文件，配合 checkpoint 做 at-least-once 恢复。 需要 exactly-once 文件清理语义时，应同时开启 ray_data_checkpoint.delete_no_checkpoint_files。

Magnus Export，推荐表型结果

Magnus 适合产出可被下游复用的规范化表。建议写清楚 schema 和分区配置，尤其是二进制、数组、嵌套字段。

写 Magnus 表YAML
export:
  target: magnus
  table_name: <db>.<table>
  operation: OVERWRITE             # default: APPEND; enum: APPEND | OVERWRITE
  create_table_if_not_exists: true # default: false; create table before write when absent
  infer_schema_on_create: false    # default: false; true only when schema is intentionally omitted
  partition_columns: ["p_date"]    # default: null; partition columns for table creation / write
  partition_values:
    p_date: "20260520"
  schema:                          # default: null; recommended for production Magnus writes
    fields:
      - {name: "id", type: "string"}
      - {name: "texts", type: "list<string>"}
      - {name: "images", type: "list<binary>"}
      - {name: "p_date", type: "string"}
  magnus_failure_policy: abort     # default: abort; enum: abort | commit_completed_unsafe
  magnus_conf:                     # default: {}
    write_options:
      write.format.default: lance

commit_completed_unsafe 仅适用于明确接受部分完成提交语义，并且理解 Ray Data checkpoint 恢复边界的任务。 常规任务建议使用 abort。

export.max_rows，用于限量验证

export.max_rows 控制传给 sink 的行数。它不是抽样算子，而是导出前的限制。 Ray limit 模式下，计算量可能减少，但属于 best effort；filter、all-to-all、已 materialize 的 dataset 或需要全量输入的算子仍可能处理更多数据。

限制导出 10 行YAML
export:
  target: magnus
  table_name: <db>.<table>_sample
  operation: OVERWRITE             # default: APPEND; enum: APPEND | OVERWRITE
  max_rows: 10                     # default: null; unset means full export
  max_rows_mode: limit             # default: limit; enum: limit | quota_reservation
  max_rows_quota_batch_size: null  # default: null; only for quota_reservation

7. Checkpoint

本文仅介绍 Ray remote 文件 source-to-sink 路径中的 ray_data_checkpoint。 它用于记录 Ray Data 写出元数据，辅助任务在失败后保留已完成的写出进度。

能力作用推荐使用场景
ray_data_checkpoint 记录 Ray Data 文件 source 到文件 sink 的写出元数据。 Ray HDFS 分布式 export，任务失败后希望保留已完成 part。
Ray Data checkpointYAML
ray_data_checkpoint:
  enabled: true                    # default: false
  dir: hdfs://<cluster>/<path>/checkpoints/{job_id}  # default: null; required when enabled
  delete_no_checkpoint_files: true   # default: false; enable when exactly-once file cleanup is required
  write_interval: null             # default: null

export:
  target: hdfs
  type: parquet
  path: hdfs://<cluster>/<path>/result/{job_id}
  mode: append                     # default: error_if_exists; enum: error_if_exists | overwrite | append
delete_no_checkpoint_files 默认为 false，适合保守保留已写 part 的恢复场景。 如果任务需要 exactly-once 文件清理语义，应设置为 true，让 Ray Data 在成功写入后删除未记录在 checkpoint metadata 中的 sink 文件。 仍建议为任务使用隔离输出路径，并结合重试策略和下游校验确认结果符合预期。

9. 核心参数

Ray remote 任务优先关注以下参数。完整参数以 loader/export 参考文档和代码为准。

参数枚举或默认值使用场景
executor_type ray 本文仅覆盖 Ray 模式。
dataset.configs[].type remote 本文仅覆盖远程数据源。
dataset.configs[].source hdfs、magnus、tqs、hive；无默认值 决定使用哪类 loader，建议显式配置；TQS 仅建议测试或小规模验证使用。
export.target hdfs、magnus；建议显式配置 决定结果交付形态。文件选 HDFS，表选 Magnus。
export.type jsonl、parquet；HDFS 默认按路径推断，无法推断时为 jsonl HDFS 文件输出推荐二选一，生产任务建议显式配置。
export.mode 默认 error_if_exists；枚举 error_if_exists、overwrite、append 控制目标路径已存在时的处理方式。
export.max_rows_mode 默认 limit；枚举 limit、quota_reservation 常规限量导出使用 limit；需要 sink 前配额语义时再考虑 quota_reservation。
ray_data_checkpoint.enabled 默认 false；枚举 true、false Ray HDFS 分布式写出且希望失败恢复时开启。
ray_data_checkpoint.delete_no_checkpoint_files 默认 false；枚举 true、false 需要 exactly-once 文件清理语义时开启，删除未记录在 checkpoint metadata 中的 sink 文件。
ray_dry_run_plan 默认 false；枚举 true、false 上线前验证 Ray plan，不真实执行重型任务。
debug.bytes_output.mode 默认 summary；枚举 summary、full_base64 默认摘要；确需完整 bytes 时再落全量 base64。

推荐文件链路

规范表交付

HDFS 或 Magnus 入，Magnus 出

11. 上线前检查

  • 输入路径、目标路径、Magnus 表名均应替换为实际资源，不应将密钥写入 YAML 或文档。
  • 本文范围内的任务固定使用 executor_type: ray，上线前建议先执行 ray_dry_run_plan: true。
  • 首次写目标表或目标目录时，建议先设置 export.max_rows 进行限量验证。
  • 写 HDFS 时确认 path 是目录路径，Ray 分布式 HDFS export 不接受单个文件路径。
  • 写 Magnus 时优先显式配置 schema，并确认分区列和值与目标表一致。
  • 需要失败恢复时，提前设计 ray_data_checkpoint.dir 和 export.mode；需要 exactly-once 文件清理语义时开启 delete_no_checkpoint_files。
  • TQS loader 不推荐大规模直接使用，也无法开启 ray_data_checkpoint；生产任务建议先物化到 HDFS Parquet。
  • Hive 仅作为次选路径。稳定性优先时，建议先物化到 HDFS，再使用 HDFS loader。
  • 单条样本异常时，使用 operator debug 输出 HDFS JSONL trace；bytes 默认使用摘要，必要时再开启全量 base64。
