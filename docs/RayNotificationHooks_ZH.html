Notification Hooks 配置说明

说明如何通过顶层 notification_hooks 给 Ray 任务发送周期飞书进度和成功/失败终态通知。 本页以当前代码实现为准，重点覆盖配置字段、卡片变量、snapshot 口径和排障方式。

适用执行器：RayExecutor Hook 类型：adc_lark_message 最小周期：30s 不会为通知触发额外 Ray Data action

Conclusion

配置入口

在 YAML 顶层配置 notification_hooks。它与 export.after_export_hook 独立，后者仍只处理 export 后同步。

发送时机

interval 存在时发送 heartbeat；RayExecutor 结束时按 on_success 或 on_failure 发送终态通知。

统计来源

通知只读取 driver snapshot、export summary 和 runtime stats actor；不执行 dataset.count() 或 materialize()。

Scope

当前第一版只覆盖 executor_type: ray 的 RayExecutor。默认 executor、非 ADC 的发送通道、Grafana/RayUI 主动查询统计不在本功能范围内。

配置原则： 任务提交系统应把接收人写入 ctx.userAccount；Data-Juicer 不做提交人身份解析。

最小配置

周期通知和终态通知都打开时，可以使用下面的配置骨架。interval 省略或写成 null 时，只发送成功/失败终态消息。

notification_hooks.yaml 
executor_type: ray
project_name: ray-notification-hook-e2e

notification_hooks:
  - type: adc_lark_message
    enabled: true
    interval: 30s          # 可选：30s、10min、1h；省略/null 表示只发终态
    on_success: true       # 成功终态是否发送
    on_failure: true       # 失败终态是否发送
    fail_on_error: false   # heartbeat 失败只 warning；终态失败是否反向影响任务
    ctx:
      userAccount: "guohongyu.7"
      apiBase: "https://ai-data-center.bytedance.net/api"
      x-tt-env: "ppe_sirius3"  # 可选，PPE 调试时使用
      x-use-ppe: "1"           # 可选，PPE 调试时使用
    template_id: "AAqtelosmXDl1"
    custom_fields:
      biz: "ecom_video"
      ray_ui_url: "https://ray.example.bytedance.net/jobs/..."
      driver_log_url: "https://log.example.bytedance.net/..."
      output_url: "hdfs://cluster/path/to/output"
    custom_stats:
      - key: "dedup.eligible_rows"
        label: "可参与去重行数"
      - key: "dedup.unique_rows"
        label: "唯一行数"
      - key: "dedup.duplicate_rows"
        label: "重复行数"
不要新增 interval_seconds。 对外配置只接受 interval 字符串；代码在运行时解析为秒。

字段说明

字段 必填 示例 说明
type 是 adc_lark_message 当前只支持 ADC 飞书模板卡片发送。
enabled 否 true 为 false 时跳过该 hook，且不校验其发送字段。
interval 否 30s、10min、1h heartbeat 周期。最小值为 30s；省略或 null 表示只发终态。
on_success 否 true 成功终态是否发送。默认按发送处理。
on_failure 否 true 失败终态是否发送。默认按发送处理。
fail_on_error 否 false 终态通知发送失败时是否抛出。heartbeat 失败始终只记录 warning。
ctx.userAccount 是 guohongyu.7 ADC OpenAPI 的接收人账号，同时会作为请求头 User-Account。
ctx.apiBase 是 https://ai-data-center.bytedance.net/api ADC API base。最终 endpoint 为 /openapi/lark/message/template-card/send-to-user。
ctx.x-tt-env、ctx.x-use-ppe 否 ppe_sirius3、1 PPE 调试头。配置后会透传到 ADC 请求 headers。
template_id 是 AAqtelosmXDl1 飞书模板卡片 ID。卡片侧变量名需要与本页变量表一致。
custom_fields 否 biz、ray_ui_url 透传到模板变量。常用于业务标识和按钮链接。
custom_stats 否 dedup.duplicate_rows 从 runtime stats actor 中筛选需要展示的统计项；未配置时 snapshot 包含 actor 中所有 stats。

interval 校验

interval 在 config 初始化阶段校验，格式必须是正整数加单位，单位仅支持 s、min、h。

合法30s、10min、1h、null、省略
非法0s、abc、10、-1h、低于 30s 的值

运行时行为

  1. RayExecutor 进入 run() 后创建 TaskNotificationManager 并启动 heartbeat timer。
  2. 任务阶段会依次更新为 load、process、export。
  3. heartbeat 读取当前 snapshot，写入 notification_snapshot.json，并发送事件 heartbeat。
  4. 任务成功后发送事件 success，失败后发送事件 failure，并把错误摘要写入 snapshot。
  5. 如果存在 job_summary.json，通知 snapshot 会同步写入 notification_snapshot 字段。

snapshot 字段

字段 来源 说明
job_idcfg.job_id任务 ID，可能由提交系统注入。
project_namecfg.project_name项目或算子名称，建议配置为可读名称。
executor_typecfg.executor_type当前版本预期为 ray。
statusmanager 状态running、success 或 failure。
phaseRayExecutor 阶段initializing、load、process、export、finished、failed。
elapsed_secondsdriver 时间从 manager 初始化到当前 snapshot 的耗时。
export_pathcfg.export_path配置中的导出路径。
output_rowsexport summary只有 exporter 已知时才填充；未知时为 null。
output_filesexport summary / 文件元数据导出完成后可从已知结果或文件元数据得到。
output_bytesexport summary / 文件元数据导出完成后可从已知结果或文件元数据得到。
custom_statsruntime stats actor由 Ray worker 侧累加，driver 周期读取。
error_summary异常摘要失败终态时填充，最长 500 字符。
性能边界： 通知模块只读取已有状态，不为了行数统计触发 dataset.count() 或 materialize()。如果某个统计无法从 exporter 或文件元数据得到，文案会显示 unknown。

飞书卡片变量

发送 payload 使用 ADC send-to-user OpenAPI，核心结构如下：

ADC request body 
{
  "userEmailOrAccount": "guohongyu.7",
  "templateId": "AAqtelosmXDl1",
  "templateVariable": {
    "event": "heartbeat | success | failure",
    "project_name": "ray-notification-hook-e2e",
    "job_id": "notification_hooks_20260527182431",
    "status_text": "进行中",
    "phase_text": "export",
    "phase_progress": "load ✓ -> process ✓ -> export 进行中",
    "elapsed_text": "50s",
    "output_rows_text": "unknown",
    "output_files_text": "2",
    "output_bytes_text": "128 B",
    "error_summary_text": "无"
  }
}

推荐变量

卡片模板建议优先绑定 snake_case 文本变量，避免 CardKit 把 URL object 或复杂对象渲染成 JSON 字符串。

卡片变量 推荐用途 示例值
project_name项目ray-notification-hook-e2e
job_id任务 IDnotification_hooks_20260527182431
user用户guohongyu.7
status_text状态角标进行中、成功、失败
phase_text当前阶段load、process、export
phase_progress阶段进度load ✓ -> process ✓ -> export 进行中
elapsed_text已运行50s、10min 5s
export_path_text输出路径hdfs://cluster/path/output
output_rows_text输出行数1000 或 unknown
output_files_text输出文件数2 或 unknown
output_bytes_text输出大小128 B、1.2 MB
error_summary_text错误信息无 或 RuntimeError: ...
ray_ui_url_text按钮 URLhttps://ray.example...
driver_log_url_text按钮 URLhttps://log.example...
output_url_text按钮 URLhdfs://cluster/path/output

CardKit 变量声明

在线卡片和本地 .card 文件中的变量声明应使用 CardKit 导出的字段结构。文本变量示例：

card-variable.json 
{
  "type": "text",
  "apiName": "project_name",
  "name": "项目",
  "desc": "Data-Juicer project_name",
  "mockData": "ray-notification-hook-e2e"
}
常见错误： 如果所有字段都显示成同一个 URL、或者把 {"url": "...", "pc_url": "..."} 作为正文渲染，通常是卡片组件绑定了 URL object 变量，或变量声明不是 CardKit 当前格式。正文和按钮 URL 建议绑定 *_text 变量。

自定义统计

custom_stats 配置的是从 runtime stats actor 中读取的 key。Ray worker 侧可以通过 RuntimeStatsCollector.increment() 累加，driver 侧 snapshot 会读取 actor 快照。

当前 dedup pipeline 写入的统计

key 含义 模板变量别名
dedup.eligible_rows 可参与去重的行数 dedup_eligible_rows_text、dedupEligibleRowsText
dedup.unique_rows 唯一行数 dedup_unique_rows_text、dedupUniqueRowsText
dedup.duplicate_rows 重复行数 dedup_duplicate_rows_text、dedupDuplicateRowsText

排障速查

现象 优先检查 处理方式
没有周期通知 interval 是否省略或为 null 需要 heartbeat 时显式配置 interval: 30s 或更长周期。
配置初始化报错 interval 格式、type 是否正确 使用 30s、10min、1h；type 写 adc_lark_message。
任务因为终态通知失败而失败 fail_on_error 非强一致通知场景建议设置 false。
输出行数显示 unknown exporter 是否提供 last_export_summary.output_rows 这是允许状态；通知不会为行数额外触发 Ray Data action。
卡片字段显示 JSON 或重复 URL 卡片变量声明和组件绑定 正文使用 *_text 变量；变量声明使用 type/apiName/name/desc/mockData。

Inference

以下是从代码行为推导出的配置建议：

  • 线上卡片正文尽量使用 *_text 变量，因为这些变量已经过格式化，能避免 null 和 URL object 的展示问题。
  • 当任务规模较大时，interval 不应设置得太短；当前最小值是 30s，生产任务可按通知噪声选择 10min 或 1h。
  • 如果通知只作为观测能力，建议保持 fail_on_error: false，避免飞书或 ADC 短暂异常影响 Ray 主任务。

Risk

  • output_rows 可能为 null。这是为了避免通知模块触发额外 Ray Data action。
  • heartbeat 是近实时 driver snapshot，终态通知在 export 完成后才会补充可获得的输出统计。
  • 外部卡片模板由飞书平台管理，模板变量发布后才会影响实际消息渲染。
  • 远端 notification_snapshot.json / job_summary.json 读取可能受平台 token 或 GDPR/ZTI 权限限制；这不代表本地 snapshot 写入逻辑失败。
