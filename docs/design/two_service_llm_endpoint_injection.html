双服务大模型部署与 VLM Endpoint 注入方案

当 Ray 内部部署链路受 vLLM 版本锁定影响，无法承载较新的多模态模型时， 将模型推理服务从数据合成 Ray 作业中拆出。两者本质上都是 Merlin 任务： 先启动 GPU LLM Merlin 任务，等待模型服务可访问，再启动数据合成 Ray Merlin 任务。 控制面在 LLM 服务就绪后发现 IPv6 地址，并把用户 YAML 中 vlm_api_response_mapper 的 base_url/endpoint/api_format 改写为该服务的 OpenAI 兼容访问地址。

独立 GPU LLM 服务 Ray 作业只负责数据处理 两者都是 Merlin 任务 OpenAI 兼容 API IPv6 bracket URL 可在控制面实现

背景与约束

vLLM 0.8.5

Ray 内部部署链路锁定的 vLLM 版本无法快速跟进较新的模型运行时需求。

OpenAI API

vlm_api_response_mapper 已按 OpenAI 兼容接口组织请求，可对接外部推理服务。

IPv6

服务发现地址通常是 IPv6，URL 中必须使用 [ipv6] bracket 写法。

Merlin

LLM 服务和数据合成 Ray 作业都按 Merlin 任务管理，控制面编排两次提交。

核心判断： Data-Juicer 不需要直接承载模型部署能力。更稳妥的边界是让控制面负责 GPU 服务生命周期与 YAML 改写， Data-Juicer 继续通过 vlm_api_response_mapper 调用 OpenAI 兼容 endpoint。

目标架构

方案拆成两个服务：第一个是 GPU LLM 服务，负责加载模型并暴露 OpenAI 兼容 API； 第二个是 Data-Juicer/Ray 作业，负责数据读取、算子执行和导出。两者都由 Merlin 承载， 控制面在两次 Merlin 任务之间做状态等待、地址发现和配置注入。

服务一：GPU LLM Merlin 任务

负责加载较新模型，选择适配的推理框架和镜像，暴露 OpenAI 兼容 API。

输出：Merlin job 标识、服务就绪状态、IPv6 地址、端口、支持的 API endpoint。

服务二：数据合成 Ray Merlin 任务

读取用户 YAML 并执行数据处理，算子通过 HTTP 调用已部署的 LLM 服务。

输入：控制面改写后的 YAML，不需要感知 GPU 服务部署细节。

控制流程

1

接收用户 YAML 与模型部署声明

控制面读取原始 pipeline，定位 vlm_api_response_mapper 节点，识别其目标 API 形态：Chat Completions 或 Responses。

2

启动独立 GPU LLM 服务

根据模型、镜像、GPU 规格、并发和上下文长度创建 LLM Merlin 任务，并等待健康检查与模型加载完成。

3

发现服务访问地址

通过 ai_data_forge 的 Merlin get 接口拿到 IPv6 与端口后，生成标准 root URL：http://[2605:...]:8001/v1。IPv6 必须带方括号。

4

改写 VLM mapper 配置

按原始 endpoint 语义改写 base_url、必要时补充 endpoint 与 api_format，保持请求 payload 类型不变。

5

提交 Data-Juicer Ray 作业

数据处理 Ray Merlin 任务只接收已注入 endpoint 的 YAML。作业结束、失败或取消时，控制面负责回收 LLM 服务。

Merlin 编排时序

控制面位于 ../ad_ai_data_center，负责把一次用户数据合成请求拆成两个 Merlin 生命周期： 先通过 ai_data_forge 拉起 LLM Merlin 任务；轮询 Merlin get 接口并做 LLM endpoint 连通性探测；确认服务可访问后，再改写 YAML 并拉起数据合成 Ray Merlin 任务。 LLM 节点从容器启动到模型 ready 可能需要几分钟到十几分钟，取决于模型大小、权重加载和 GPU 资源调度。

启动入口

ad_ai_data_center 现有数据合成任务会调用 aiDataForgeClient.LaunchMerlinJobRun 或 LaunchMerlinFederalJob，LLM 服务任务可以复用同类入口。

状态与地址发现

控制面通过 GetMerlinJobRun / GetMerlinFederalJob 轮询状态，并从 Merlin 详情中解析 LLM 节点 IP、端口和 endpoint。

可用性门禁

只有当 Merlin 状态进入 running 且一次最小 OpenAI 兼容请求成功后，才允许提交数据处理 Ray 任务。

接口补齐点： 当前 ai_data_forge 的 MerlinJobRunDTO 主要暴露 merlin_job_run_id、status、progress_percent 和 error_message。如果标准 GetMerlinJobRun 需要直接返回 LLM endpoint，建议在 ai_data_forge 侧补充 endpoint/IP 字段，或通过 Merlin 详情字段结构化透传； Federal Job 路径可复用 GetMerlinFederalJob 的详情结果承载扩展信息。

已确认设计决策

本节记录当前讨论后收敛的产品和控制面约束。后续如果进入实现，应优先按这些约束拆分 ad_ai_data_center 的任务配置、运行实例状态和 Merlin 编排逻辑。

主题 确认决策 实现含义
用户可见性 LLM Merlin 任务对用户隐藏，但暴露阶段状态。 用户看到一个数据合成实例；列表/详情可展示 WAITING_LLM_READY、DATA_RAY_RUNNING 等阶段。
状态存储 第一版写入现有 SynthesisInstanceProperties，不新建表。 新增 stage、llmServing、dataProcessing 等扩展字段；主实例状态不扩展。
Ready 判定 Merlin RUNNING -> /readyz 或 /health OK -> OpenAI 最小请求成功。 Merlin running 只作为前置条件；最终以实际 chat/responses endpoint 最小请求成功为准。
配置位置 llmServingConfig 是新建/更新任务请求的独立配置，不进入 Data-Juicer YAML。 建议加在 RayTaskUpsertRequest 顶层，并持久化到任务版本 properties。
运行期 YAML 控制面内部生成 resolved YAML 或等价执行配置，但不向普通用户展示。 任务版本展示原始 YAML；内部保存 resolved endpoint 摘要，必要时保存 resolved YAML 供排障。
base_url 启用 LLM Serving 后，用户 YAML 中 base_url 可以省略。 API 形态按 api_format / endpoint 判断；都缺省时按 Chat Completions。
多 mapper 第一版最多拉起一个 LLM 服务，多个 vlm_api_response_mapper 必须共享同一 serving spec。 所有 mapper 的 model、API 形态、endpoint 语义必须一致；不一致则拒绝运行。
模型一致性 mapper.model 为空时由控制面注入；不为空时必须等于 llmServingConfig.model。 模型不一致时强失败，不做静默覆盖。
生命周期 LLM Merlin 任务绑定单次数据合成实例。 LLM ready 后提交数据处理 Ray 任务；数据处理终态后同步停止 LLM Merlin 任务。
取消 取消时按 stage 停止相关 Merlin job；数据处理已运行时先停 Ray，再停 LLM。 如果还在等待 LLM ready，则只停止 LLM Merlin 任务，不提交数据处理任务。
回收失败 回收失败不覆盖主任务业务结果，只更新 LLM 子状态。 例如主任务 SUCCEEDED 但 llmServing.status=CLEANUP_FAILED；补偿能力统一记录在 TODO 章节。
运行中故障 Ray 任务运行中 LLM 请求失败，由 mapper retry / error_key / fail_on_error 处理。 运行中恢复和流量切换能力统一记录在 TODO 章节。

默认值

runtime 缺省为 vllm，第一版只支持 vllm；port 缺省为 8001；basePath 第一版固定 /v1。

默认镜像

镜像可覆盖；不配置时使用 hub.byted.org/arnold/life.gen_ai.lifellm_env:9500dc6dbc7ff0ce96920939ebde75f6。运行实例需记录 resolved image。

资源格式

resource 复用 RayTaskRunNode 字段语义；第一版 number 只能为 1，多卡通过 gpu 表达。

鉴权处理： 当前 LLM Serving 服务按无鉴权处理。启用 LLM Serving 时，控制面生成的内部执行 YAML 应移除 mapper 中的 api_key 和 extra_headers.Authorization，其他 headers 可保留。

提交运行请求 SUBMITTING_LLM PENDING -> SUBMITTED PENDING 调用 LaunchMerlinJobRun 创建 LLM Merlin 任务。
LLM Merlin running WAITING_LLM_READY MERLIN_RUNNING -> PROBING PENDING 解析 endpoint JSON，执行 /readyz 或 /health，再做 OpenAI 最小请求。
LLM 探活成功 SUBMITTING_DATA_RAY READY SUBMITTED 生成内部 resolved YAML，提交数据处理 Ray Merlin 任务。

Endpoint 适配规则

当前 VlmApiResponseMapper 的 URL 拼接规则是：如果 base_url 已经以 /chat/completions 或 /responses 结尾，则直接使用；否则把 endpoint 追加到 base_url 后面。Responses API 的判定来自显式 api_format: responses，或 endpoint/base_url 以 /responses 结尾。

原始语义 推荐注入方式 最终请求 URL 说明
默认 Chat Completions base_url: http://[ipv6]:8001/v1 http://[ipv6]:8001/v1/chat/completions 保留默认 endpoint: /chat/completions。
显式 Chat endpoint base_url: http://[ipv6]:8001/v1
endpoint: /chat/completions		 http://[ipv6]:8001/v1/chat/completions 适合原 YAML 已声明 endpoint 的情况，改写后语义清晰。
Responses API base_url: http://[ipv6]:8001/v1
endpoint: /responses
api_format: responses		 http://[ipv6]:8001/v1/responses 同时锁定 URL 与 payload 形态，避免误走 Chat payload。
完整 endpoint 已存在 base_url: http://[ipv6]:8001/v1/responses http://[ipv6]:8001/v1/responses mapper 会识别完整 endpoint，不再重复追加。
不建议： 控制面不要只做字符串替换，把原始 base_url 的 host 换成 IPv6。 这样容易把 /api/v3/responses、/v1、 /chat/completions 等路径混在一起，导致重复路径或 payload 类型错误。

YAML 改写策略

Chat Completions 场景的内部执行配置会注入 root URL，并复用 mapper 默认 endpoint；用户任务版本 YAML 中可以省略 base_url。

- vlm_api_response_mapper:
    image_key: "images"
    output_key: "qwen_response"
    model: "qwen3vl"
    base_url: "http://[2605:340:cd51:603:7dd5:e521:38d0:fe5c]:8001/v1"
    # endpoint 默认是 /chat/completions
    temperature: 0.1
    max_tokens: 2048
    rpm: 120
    tpm: 500000

Responses 场景的内部执行配置必须同时表达 endpoint 与 payload 形态；用户任务版本 YAML 中可以只保留 api_format / endpoint 语义。

- vlm_api_response_mapper:
    image_keys: ["main_image", "detail_images"]
    output_key: "ocr_answer"
    model: "qwen3vl"
    base_url: "http://[2605:340:cd51:603:7dd5:e521:38d0:fe5c]:8001/v1"
    endpoint: "/responses"
    api_format: "responses"
    text:
      format:
        type: "json_object"
    store: false
    rpm: 120
    tpm: 500000

控制面可用结构化 YAML parser 生成内部 resolved YAML，避免正则替换破坏注释、缩进或多算子配置；该 resolved YAML 不向普通用户展示。

def inject_llm_endpoint(mapper_cfg, service):
    api_kind = detect_api_kind(mapper_cfg)
    root = f"http://[{service.ipv6}]:{service.port}/v1"

    mapper_cfg["base_url"] = root
    if api_kind == "responses":
        mapper_cfg["endpoint"] = "/responses"
        mapper_cfg["api_format"] = "responses"
    else:
        mapper_cfg["endpoint"] = "/chat/completions"
        mapper_cfg.pop("api_format", None)

    return mapper_cfg

检测 API 类型

优先使用用户显式配置：api_format。没有显式配置时，再看 endpoint 和 base_url 是否以 /responses 结尾。

保留业务参数

prompt_template、messages_template、input_template、extra_body、限流参数等都不应被控制面改写。当前无鉴权时，应移除 api_key 和 Authorization header。

实现边界

优先放在控制面

服务编排、GPU 配额、IPv6 服务发现、健康检查、失败回收、YAML patch 与作业提交天然属于控制面职责。

控制面代码位于 ../ad_ai_data_center。Data-Juicer 仓库只需要保持 mapper 的 endpoint 契约清晰，并提供文档或可选工具函数。

仓库内可选能力

如果需要在本仓库落地，可以新增一个纯配置转换工具，输入原 YAML 和服务发现结果，输出改写后的 YAML。

该工具不应负责启动 GPU 服务，也不应把具体平台 API 写进算子实现。

职责 建议归属 原因
GPU 服务创建、扩缩容、回收 ../ad_ai_data_center 依赖平台资源、服务账号、网络和配额，不适合塞进数据处理仓库；LLM 服务本身也按 Merlin 任务提交。
IPv6/端口发现与健康检查 ../ad_ai_data_center + ../ai_data_forge 控制面轮询 GetMerlinJobRun / GetMerlinFederalJob，从 Merlin 详情获取地址并做 HTTP 探活。

风险与治理

Endpoint 语义错配

Responses 请求如果只改 URL，不设置 api_format: responses，可能仍按 Chat payload 发送。

治理：改写时同时锁定 endpoint 和 api_format。

IPv6 URL 格式

原始 IPv6 不能直接拼到 URL host 中，必须写成 http://[ipv6]:port。

治理：使用 URL builder 或专门的 host formatter。

服务就绪不等于端口可达

容器启动后模型权重可能仍在加载，过早提交 Ray 作业会造成批量请求失败。

治理：健康检查需要覆盖模型 ready 与一次最小推理。

网络可达性

Ray worker 到 GPU 服务之间需要网络可达；当前 LLM Serving 按无鉴权处理。

治理：在控制面做连通性预检，并从内部执行 YAML 中移除旧的 api_key / Authorization。

并发和限流

服务侧吞吐和 mapper 的 rpm/tpm、Ray 并发度需要匹配，否则会压垮单服务。

治理：由部署声明给出推荐限流，控制面可填充 mapper 限流参数。

资源泄露

Ray 作业失败或被取消时，独立 LLM 服务可能继续占用 GPU。

治理：控制面同步回收；补偿扫描见 TODO 章节。

Merlin get 字段缺口

如果 GetMerlinJobRun 只返回状态而不返回 endpoint，控制面无法稳定拼出 LLM 服务地址。

治理：在 ai_data_forge 返回中补齐 IP/port/endpoint，或结构化透传 Merlin 详情。

灰度验收

A

离线 YAML patch 验证

对 Chat 与 Responses 各准备一个样例 YAML，检查 patch 后 URL 只出现一次 endpoint，且 API 类型不变。

B

LLM Merlin 任务等待与连通性验证

控制面先拉起 LLM Merlin 任务，轮询状态和 endpoint；在提交 Ray 作业前，对注入后的 URL 发起一次最小请求，验证路径和 payload 均可用。

C

小批量 Data-Juicer 作业

用少量样本验证 mapper 的输出字段、错误字段、限流参数和响应解析行为。

D

任务级监控和回收

确认 Ray 作业结束、失败、取消时，LLM 服务都能被回收；同时记录请求量、延迟、错误率和 GPU 利用率。

代码依据

Mapper URL 拼接契约

data_juicer/ops/mapper/qa/vlm_api_response_mapper.py 中 _api_url() 会在 root base_url 后追加 endpoint，但完整 endpoint 不会重复追加。

if base_url.endswith(("/chat/completions", "/responses")):
    return base_url
endpoint = self.endpoint if self.endpoint.startswith("/") else f"/{self.endpoint}"
if base_url.endswith(endpoint):
    return base_url
return f"{base_url}{endpoint}"

Responses API 判定契约

_is_responses_api() 优先相信 api_format，因此控制面改写 Responses 场景时应显式设置。

if self.api_format is not None:
    return self.api_format == "responses"
endpoint = self.endpoint.rstrip("/")
base_url = (self.base_url or "").rstrip("/")
return endpoint.endswith("/responses") or base_url.endswith("/responses")

控制面已有 Merlin 提交路径

../ad_ai_data_center 的数据合成任务已经通过 aiDataForgeClient 调用 Merlin job-run 接口，并把返回的 merlinJobRunId 写入实例属性。

LaunchMerlinJobRunResponse response =
    aiDataForgeClient.LaunchMerlinJobRun(request);
String merlinJobRunId = resolveMerlinJobRunId(response);

ai_data_forge Merlin get 接口

../ai_data_forge 的 Thrift 面提供 LaunchMerlinJobRun、GetMerlinJobRun、LaunchMerlinFederalJob 和 GetMerlinFederalJob。本方案的 IP/endpoint 发现应复用这层入口。

LaunchMerlinJobRunResponse LaunchMerlinJobRun(...)
GetMerlinJobRunResponse GetMerlinJobRun(...)
LaunchMerlinFederalJobResponse LaunchMerlinFederalJob(...)
GetMerlinFederalJobResponse GetMerlinFederalJob(...)
仓库内已有 YAML 使用 http://[ipv6]:8001/v1 作为 base_url，这与本方案的 root URL 注入方式一致； 另有示例使用完整 /responses endpoint，说明控制面需要保留 API 类型语义。
